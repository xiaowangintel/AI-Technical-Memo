### Lines 70–113: GEMM specification comments / GEMM 规格注释

```cpp
using namespace cute;

// D (f32) = beta*C (f32) + alpha*A (f16) * B (f16)
// A: MxK, K-major  B: NxK, K-major  C/D: MxN, N-major
//
// Steps:
//  1. GMEM->SMEM via cooperative_copy   (A, B)
//  2. tcgen05.mma  A,B -> TMEM acc
//  3. tcgen05.ld   TMEM acc -> RMEM
//  4. GMEM->RMEM   C
//  5. axpby        alpha*acc + beta*C in RMEM
//  6. RMEM->GMEM   D
//
// TypeA = TypeB = half_t;  TypeC = TypeD = TypeAccumulator = float;
```

**EN**: Specifies the **six-step data pipeline**. SM100 introduces TMEM as a new on-chip memory tier between SMEM and registers. `tcgen05.mma` always writes accumulators to TMEM (never to registers); a separate `tcgen05.ld` instruction (wrapped by `make_tmem_copy`) is required to move them to the register file before the epilogue. All types are listed explicitly to prevent confusion between F16 compute inputs and F32 accumulator/output.  
**CN**: 指定**六步数据流水线**。SM100 引入 TMEM 作为 SMEM 与寄存器之间的新片上内存层。`tcgen05.mma` 始终将累加器写入 TMEM（而非寄存器）；必须使用单独的 `tcgen05.ld` 指令（由 `make_tmem_copy` 封装）将其移至寄存器文件，然后才能执行尾声。所有类型均明确列出，以避免 F16 计算输入与 F32 累加器/输出之间的混淆。

### Lines 114–132: `SharedStorage` struct / 共享内存结构体

```cpp
#if defined(CUTLASS_ARCH_MMA_SM100_SUPPORTED)

template <class TypeA, class TypeB, class ASmemLayout, class BSmemLayout>
struct SharedStorage
{
  alignas(128) cute::ArrayEngine<TypeA, cute::cosize_v<ASmemLayout>> A;
  alignas(128) cute::ArrayEngine<TypeB, cute::cosize_v<BSmemLayout>> B;

  alignas(16) cute::uint64_t mma_barrier;
  alignas(16) cute::uint32_t tmem_base_ptr;

  CUTE_DEVICE constexpr auto tensor_sA() {
    return make_tensor(make_smem_ptr(A.begin()), ASmemLayout{});
  }
  CUTE_DEVICE constexpr auto tensor_sB() {
    return make_tensor(make_smem_ptr(B.begin()), BSmemLayout{});
  }
};
```

**EN**: This struct is placed in **dynamic shared memory** (SMEM). Key members:  
- `alignas(128)` — UMMA hardware requires 128-byte alignment for operand buffers.  
- `cute::cosize_v<Layout>` — Compile-time co-size (minimum flat array size) for the swizzled layout; ensures the SMEM array is large enough to hold all elements including swizzle padding.  
- `mma_barrier` — 64-bit phase-based SMEM barrier. Warp 0 signals this after `tcgen05.mma` finishes, letting all threads proceed to load the next K-tile.  
- `tmem_base_ptr` — 32-bit TMEM base address, written by warp 0's allocator call and then read by all threads after `__syncthreads`.  
- `tensor_sA/B()` — Return typed `Tensor` views with the swizzled layout; avoids raw pointer arithmetic.  

**CN**: 该结构体放置在**动态共享内存**（SMEM）中。关键成员：  
- `alignas(128)` — UMMA 硬件要求操作数缓冲区 128 字节对齐。  
- `cute::cosize_v<Layout>` — 给定 swizzle 布局的编译期协尺寸（最小平坦数组大小），确保 SMEM 数组足够容纳含 swizzle 填充的所有元素。  
- `mma_barrier` — 64 位基于相位的 SMEM 屏障。warp 0 在 `tcgen05.mma` 完成后发出信号，允许所有线程继续加载下一个 K-tile。  
- `tmem_base_ptr` — 32 位 TMEM 基地址，由 warp 0 的分配器调用写入，`__syncthreads` 后所有线程读取。  
- `tensor_sA/B()` — 返回带有 swizzle 布局的类型化 `Tensor` 视图；避免原始指针运算。

### Lines 217–249: Fragment allocation — SMEM descriptors & TMEM accumulator / 片段分配——SMEM 描述符与 TMEM 累加器


**EN**: Two key SM100-specific behaviors:  
1. `make_fragment_A/B` — For `tcgen05.mma`, these do **not** allocate register arrays. They return `UMMA::DescriptorIterator` objects, which are compact (64-bit) SMEM descriptors encoding the address and swizzle pattern. The hardware uses these descriptors to DMA data from SMEM into the MMA datapath.  
2. `make_fragment_C` — Returns a `Tensor` backed by **TMEM** (tensor memory), the new SM100 on-chip memory exclusively for accumulators. TMEM is physically on the SM but separate from both SMEM and the register file; it can hold 512 columns × 32 rows of 32-bit elements.  

**CN**: 两个 SM100 特有行为：  
1. `make_fragment_A/B` — 对于 `tcgen05.mma`，这些函数**不**分配寄存器数组。它们返回 `UMMA::DescriptorIterator` 对象——紧凑的（64 位）SMEM 描述符，编码地址和 swizzle 模式。硬件使用这些描述符将数据从 SMEM DMA 到 MMA 数据路径。

### Lines 231–248: TMEM allocation & broadcast / TMEM 分配与广播

```cpp

uint32_t elect_one_warp = (threadIdx.x / 32 == 0);
```

**EN**: TMEM must be allocated before first use. Only warp 0 calls `allocate`, requesting the full SM100 TMEM capacity (typically 512 columns). **CN**: TMEM 必须在首次使用前分配。只有 warp 0 调用 `allocate`，请求完整的 SM100 TMEM 容量（通常为 512 列）。分配的基地址存储在 SMEM（`tmem_base_ptr`）中，以便所有线程在 `__syncthreads` 后读取。每个线程随后将 `tCtAcc.data()` 设置为此地址，使所有线程对 TMEM 中的累加器张量有一致的视图。在 `tcgen05.mma` 之前未分配 TMEM 会导致未定义行为。

### Lines 260–298: Mainloop — cooperative_copy + tcgen05.mma + barrier / 主循环——协作拷贝 + tcgen05.mma + 屏障

```cpp
tiled_mma.accumulate_ = UMMA::ScaleOut::Zero;  // First MMA: zero-init TMEM acc

for (int k_tile = 0; k_tile < size<3>(tCgA); ++k_tile) {

  // Step 2a: GMEM -> SMEM via auto-vectorized cooperative copy
  cooperative_copy<128>(threadIdx.x, tCgA(_,_,_,k_tile), tCsA);
  cooperative_copy<128>(threadIdx.x, tCgB(_,_,_,k_tile), tCsB);
  __syncthreads();  // Wait for SMEM to be populated

  // Step 2b: tcgen05.mma (single-warp dispatch)
  if (elect_one_warp) {
    for (int k_block = 0; k_block < size<2>(tCrA); ++k_block) {
      gemm(tiled_mma, tCrA(_,_,k_block), tCrB(_,_,k_block), tCtAcc);
      tiled_mma.accumulate_ = UMMA::ScaleOut::One;  // Accumulate from 2nd k_block on
    }
    cutlass::arch::umma_arrive(&shared_storage.mma_barrier);
  }
  cute::wait_barrier(shared_storage.mma_barrier, mma_barrier_phase_bit);
  mma_barrier_phase_bit ^= 1;
}
```

**EN**: The K-tile mainloop has three sub-phases per iteration:  
1. **`cooperative_copy<128>`** — Distributes the GMEM→SMEM load across all 128 threads. CuTe automatically selects the widest safe vector width (up to 128-bit = `float4`). One call handles the full MmaTile_M×MmaTile_K A-tile; another handles MmaTile_N×MmaTile_K for B.  
2. **`gemm` / `tcgen05.mma`** — Only warp 0 enters this block. The `gemm` call resolves to the appropriate `tcgen05.mma` PTX instruction via CuTe's dispatch mechanism. The inner `k_block` loop runs the K-blocks within the K-tile (4 blocks, since MmaK=16 and MmaTile_K=64). `ScaleOut::Zero` on the first block clears the TMEM accumulator; `ScaleOut::One` on subsequent blocks accumulates.  
3. **Barrier** — `umma_arrive` is issued by warp 0 once the MMA pipeline is committed (the instruction is issued asynchronously to the MMA datapath). All threads then wait on the barrier before the next `cooperative_copy` overwrites SMEM.  

**CN**: K-tile 主循环每次迭代有三个子阶段：  
1. **`cooperative_copy<128>`** — 将 GMEM→SMEM 加载分配给所有 128 个线程。CuTe 自动选择最宽的安全向量宽度（最多 128 位 = `float4`）。一次调用处理完整的 MmaTile_M×MmaTile_K A tile；另一次处理 B 的 MmaTile_N×MmaTile_K。  
2. **`gemm` / `tcgen05.mma`** — 只有 warp 0 进入此块。`gemm` 调用通过 CuTe 的分发机制解析为适当的 `tcgen05.mma` PTX 指令。内层 `k_block` 循环运行 K-tile 内的 K 块（4 个块，因为 MmaK=16 而 MmaTile_K=64）。第一个块的 `ScaleOut::Zero` 清零 TMEM 累加器；后续块的 `ScaleOut::One` 进行累加。  
3. **屏障** — warp 0 在 MMA 管线提交后发出 `umma_arrive`（指令异步发往 MMA 数据路径）。然后所有线程等待屏障，再由下一次 `cooperative_copy` 覆写 SMEM。

## Key Concepts / 关键概念

- **`tcgen05.mma`** — Blackwell SM100 cluster-scoped MMA instruction; single-thread dispatch; reads A/B from SMEM via descriptors; writes to TMEM / Blackwell SM100 簇作用域 MMA 指令；单线程分发；通过描述符从 SMEM 读取 A/B；写入 TMEM
- **TMEM (Tensor Memory)** — SM100's new on-chip accumulator tier; faster than SMEM for accumulator reuse; requires explicit alloc/free / SM100 新型片上累加器层；累加器复用比 SMEM 更快；需要显式分配/释放
- **`UMMA::DescriptorIterator`** — Compact 64-bit SMEM descriptor used as A/B operand for tcgen05.mma; not a register array / 用作 tcgen05.mma A/B 操作数的紧凑 64 位 SMEM 描述符；不是寄存器数组
- **`cooperative_copy<N>`** — Auto-vectorized cooperative GMEM→SMEM copy across N threads / 跨 N 个线程的自动向量化协作 GMEM→SMEM 拷贝
- **`UMMA::tile_to_mma_shape` + `Layout_K_SW128_Atom`** — Constructs the 128-byte-swizzled SMEM layout required by UMMA hardware / 构造 UMMA 硬件所需的 128 字节 swizzle SMEM 布局
- **Phase-based barriers** — SMEM barriers with alternating `phase_bit` prevent ABA races across K-tile iterations / 带交替 `phase_bit` 的 SMEM 屏障，防止 K-tile 迭代间的 ABA 竞争
- **`SM100_MMA_F16BF16_SS`** — Tag selecting F16×F16→F32 tcgen05.mma with SMEM-SMEM operand sources / 选择 SMEM-SMEM 操作数来源的 F16×F16→F32 tcgen05.mma 的标签
- **mma_tiler vs cta_tiler** — SM100 partitions work at MMA (cluster) granularity; SM90 partitions at CTA granularity / SM100 在 MMA（簇）粒度划分工作；SM90 在 CTA 粒度划分
